# Prepped 기술 명세

상태: v0.1.0 기준
마지막 갱신: 2026-08-16

## 1. 제품 목적

Prepped는 시니어 사용자가 키오스크에서 겪는 가장 큰 병목을 결제 직전까지의 메뉴 탐색·선택 과정으로 가정한다. 사용자는 휴대폰에서 자주 먹는 메뉴 조합을 한 번 저장하고, 키오스크에서 개인 QR 하나를 스캔해 선택 단계를 줄인다.

현재 버전은 제품 가설을 검증하는 프런트엔드 데모다. 실제 매장 메뉴 조회, 주문 생성, 결제는 백엔드 API가 확정된 뒤 연결한다.

## 2. 사용자 표면

| 경로 | 대상 기기 | 역할 |
|---|---|---|
| `/` | 모바일 | 메뉴 조합 선택·저장, 매장별 설정 조회·수정, QR 표시와 매장별·전체 공유 링크 복사 |
| `/kiosk` | 노트북·키오스크 | 카메라 또는 샘플 코드로 QR 인식, 원문과 파싱된 메뉴 ID 표시, 결제 데모 |

모바일 화면의 하단 탐색은 `내 QR`, `메뉴 만들기`, `내 설정` 세 항목이다. 현재 항목은 `aria-current="page"`로 식별하며, 키오스크는 모바일 하단 탐색을 공유하지 않는 독립 화면이다.

## 3. 메뉴 선택 모델

메뉴 생성은 세 단계로 진행한다.

1. 매장: 맥도날드, 서브웨이
2. 카테고리: 버거, 사이드, 음료
3. 실제 메뉴: ID, 이름, 가격을 가진 메뉴 목록

v0.1.0에서 선택 가능한 데이터는 맥도날드 mock만 제공한다. 서브웨이는 매장 목록에 `준비 중` 상태로 보이지만 선택할 수 없다.

### 3.1 McDonald mock ID

| 범위 | 카테고리 | 예시 |
|---|---|---|
| 101–104 | 버거 | 빅맥, 불고기 버거, 1955 버거, 맥스파이시 상하이 버거 |
| 201–203 | 사이드 | 후렌치 후라이, 맥너겟 6조각, 해쉬 브라운 |
| 301–303 | 음료 | 코카콜라, 아메리카노, 바닐라 쉐이크 |

메뉴 ID는 현재 mock 데이터와 QR을 연결하는 식별자다. 실데이터 연동 시에도 화면이 가격이나 이름을 QR에 복제하지 않고 메뉴 ID를 기준으로 API 결과를 표시하도록 유지한다.

### 3.2 선택과 저장

- 메뉴 카드는 다중 선택한다.
- `선택 메뉴` 바는 선택 개수, 총액, 목록 진입점을 제공한다.
- 목록의 `저장하기`가 현재 매장의 조합을 확정한다.
- 저장하면 `내 QR`로 돌아가 QR 문자열과 이미지가 즉시 갱신된다.
- QR 정보 영역의 매장 `공유` 버튼은 해당 매장 그룹만 담은 링크를 복사한다.
- 메인 QR 카드의 `전체 링크 복사`는 현재 QR의 모든 매장 그룹을 담은 링크를 복사한다.

### 3.3 내 설정 메뉴

- 하단 탐색의 `내 설정`은 매장별 설정 카드를 보여준다.
- 맥도날드 카드는 저장 ID를 mock 목록에서 조회해 메뉴 이름, 현재 가격, 개수와 합계를 표시한다.
- 저장 메뉴가 있으면 `QR 사용 중`으로 표시한다. QR 화면에서 매장별 공유 링크를 바로 복사할 수 있다.
- 매장 카드의 `메뉴 바꾸기`는 해당 매장이 선택된 상태로 카테고리 단계부터 열고 새 조합을 만들 수 있도록 선택 메뉴를 모두 비운다.
- 편집 초안은 `savedIds`와 분리한다. 뒤로가기로 편집을 종료하거나 다른 하단 탭으로 이동하려 하면 저장 확인 모달을 표시한다.
- 모달의 안전한 기본 행동은 `저장하지 않음`이며 초기 포커스를 받는다. 이 행동은 초안을 버리고 기존 저장 메뉴를 그대로 유지한다.
- 초안에 메뉴가 있을 때만 모달의 `저장하기`를 사용할 수 있으며, 명시적으로 저장한 경우에만 `savedIds`와 QR을 갱신한다.
- 하단 탐색의 `메뉴 만들기`는 여러 매장 중 새 조합을 만들 수 있도록 매장 선택 단계부터 연다.
- 서브웨이는 메뉴 데이터가 없는 동안 `설정 없음`과 `준비 중` 상태로 표시하며 선택 행동을 제공하지 않는다.
- 설정 화면의 이름과 가격은 표시용 파생 데이터다. 저장소와 QR에는 기존처럼 메뉴 ID만 유지한다.

## 4. QR 데이터 계약

### 4.1 문법

```text
payload     = store-group *(";" store-group)
store-group = store-key "={" [menu-id *("," menu-id)] "}"
store-key   = 1*(ALPHA / DIGIT / "_" / "-")
menu-id     = 1*(ALPHA / DIGIT / "_" / "-")
```

예시:

```text
mcdonald={101,201,301}
mcdonald={101,201};subway={401,402}
```

### 4.2 현재 serializer

- 맥도날드 저장 ID가 있으면 `mcdonald={...}`를 만든다.
- 포함된 매장이 없으면 빈 상태를 나타내는 `menu={}`를 만든다.
- `qrcode` 라이브러리가 문자열을 QR 이미지로 변환한다.
- QR 오류 정정 수준은 `M`, 출력 기준 폭은 720px다.

### 4.3 현재 parser

키오스크는 `/([a-zA-Z0-9_-]+)=\{([^}]*)\}/g` 패턴으로 모든 매장 그룹을 찾는다. 각 그룹의 본문을 쉼표로 나눠 공백과 빈 값을 제거하고 `{ store, ids[] }` 구조로 표시한다.

파서는 알 수 없는 매장 키도 보존한다. 백엔드 연결 전에는 유효성이나 존재 여부를 단정하지 않고 인식된 원문을 항상 함께 보여준다.

### 4.4 공유 URL

공유 URL은 사이트 루트의 `qr` query 하나에 기존 payload를 percent-encoding한다.

```text
https://example.com/?qr=mcdonald%3D%7B101%2C201%7D
```

- 전체 공유는 표시 중인 payload 전체를 사용한다.
- 매장별 공유는 payload에서 정확히 일치하는 `store-key` 그룹 하나만 추출한다.
- `qr` parameter가 없으면 기기의 로컬 QR을 표시한다. parameter가 여러 개이거나 문법이 잘못되면 공유값을 무시하고 로컬 QR과 오류 안내를 표시한다.
- store key와 menu ID는 영문·숫자·underscore·hyphen만 허용한다. 공백, 빈 ID, 중복 store, 중복 ID와 1,500자를 넘는 payload는 거부한다.
- 공유 payload는 별도 `sharedPayload`에만 보관한다. `savedIds` 또는 `localStorage`에 기록하지 않는다.
- Clipboard API를 우선하고 권한 거부·미지원 환경에서는 임시 textarea 복사를 시도한다. 최종 성공·실패는 `role="status"` 또는 `role="alert"`로 안내한다.
- `내 QR 보기`는 URL에서 `qr` query를 제거하고 로컬 QR로 돌아가며 저장 메뉴는 변경하지 않는다.

## 5. 로컬 상태와 개인 QR

개인당 QR은 화면에서 한 개만 관리하며, 여러 매장 조합이 생기면 한 문자열 안에 매장 그룹을 합친다.

현재 영속 상태는 브라우저 `localStorage`의 `onemeal-menu-v1` 키에 저장한다.

```ts
type StoredMenu = {
  savedIds: number[];
  storeEnabled: boolean;
};
```

`storeEnabled`는 이전 버전 저장값을 읽을 수 있도록 남긴 호환 필드이며 새 UI는 항상 `true`를 기록한다. 매장 포함 토글은 더 이상 제공하지 않는다.

이 저장소는 기기 로컬 상태다. 사용자 계정, 서버 백업, 기기 간 동기화를 제공하지 않는다. 제품명 변경과 공유 기능 추가에서도 기존 데모 사용자의 조합을 보존하기 위해 저장 키를 유지한다. URL의 `sharedPayload`는 이 구조와 분리된다.

## 6. QR 생성·스캔 흐름

```text
모바일 메뉴 선택
  → 선택 목록 저장
  → 매장 키 + 메뉴 ID 직렬화
  → QR 이미지 생성
  → 전체 또는 매장별 공유 링크 복사 (선택)
  → 공유받은 기기에서 읽기 전용 QR 표시 (선택)
  → 키오스크 카메라 프레임
  → jsQR 원문 인식
  → 매장 그룹과 메뉴 ID 파싱
  → 원문·ID 표시
  → 결제 데모
```

키오스크는 `navigator.mediaDevices.getUserMedia`로 카메라를 요청하고 비디오 프레임을 캔버스에 그린 뒤 `jsQR`로 읽는다. 인식에 성공하면 카메라 트랙을 중지한다. 카메라를 사용할 수 없는 환경에서는 샘플 QR 버튼으로 후속 화면을 확인한다.

## 7. 미래 백엔드 API 경계

API 명세가 확정되면 키오스크 parser 결과를 다음 개념 요청으로 변환한다.

```json
{
  "store": "mcdonald",
  "menuIds": ["101", "201", "301"]
}
```

백엔드는 매장 키와 메뉴 ID를 검증하고 현재 이름, 가격, 판매 여부, 옵션 정보를 반환한다. 프런트엔드는 QR에 들어 있던 가격이나 이름을 신뢰하지 않고 응답 데이터를 주문 목록에 표시한다.

API 연결 전후의 계약 경계는 다음과 같다.

- QR: 매장 키와 메뉴 ID만 전달
- 키오스크 프런트엔드: 원문 보존, 문법 파싱, API 요청 구성
- 백엔드: ID 유효성, 매장 소속, 가격·판매 상태의 진실 원천
- 결제 시스템: 검증된 주문과 금액을 받아 별도 처리

## 8. PWA와 배포

- Web App Manifest: `/manifest.webmanifest`
- Service Worker: `/sw.js`
- 시작 경로와 scope: `/`
- 표시 모드: `standalone`
- 기본 방향: `portrait`
- Sites 프로젝트 연결: `.openai/hosting.json`

카메라 접근은 보안 컨텍스트가 필요하므로 프로덕션에서는 HTTPS를 사용한다. 서비스 워커는 앱 셸과 필수 정적 자산을 캐시하지만, 장래의 메뉴 API 응답은 데이터 신선도 정책이 정해지기 전까지 무조건 캐시하지 않는다.

## 9. 접근성·UX 원칙

- 큰 글자, 높은 대비, 충분한 터치 영역을 우선한다.
- 한 화면의 핵심 행동을 하나로 제한하고 선택 단계 진행 상태를 보여준다.
- 색상만으로 선택 여부를 표현하지 않고 체크 표시와 `aria-pressed`를 사용한다.
- 매장별·전체 공유는 동작 대상을 포함한 접근성 이름, 최소 44px 이상의 터치 영역과 텍스트 레이블을 제공한다.
- 복사 결과와 잘못된 공유 링크는 색상만이 아니라 `status`·`alert` 텍스트로 알린다.
- 하단 탐색은 텍스트와 아이콘을 함께 제공하고 현재 화면을 `aria-current`로 표시한다.
- 설정 화면은 QR 상태를 텍스트 배지로 제공하고 매장별 메뉴를 구조화된 목록으로 표시한다.
- 카메라 오류 시 권한 확인 안내와 카메라 없는 대체 흐름을 제공한다.
- 불필요한 설명을 줄이되 결과, 가격, 선택 개수, 저장 성공처럼 다음 행동에 필요한 정보는 숨기지 않는다.

## 10. 개인정보·보안

- v0.1.0은 이름, 이메일, 결제 정보 같은 개인정보를 수집하거나 저장하지 않는다.
- 메뉴 조합은 현재 기기의 브라우저 저장소에만 존재한다.
- QR은 비밀 토큰이 아니며 카메라에 보이는 누구나 내용을 읽을 수 있다.
- 공유 링크도 비밀 토큰이 아니며 URL을 받은 누구나 포함된 매장 키와 메뉴 ID를 읽을 수 있다.
- 공유 query는 허용 문자·그룹 문법·중복·길이를 클라이언트에서 검사하고, 향후 백엔드는 같은 입력을 다시 검증해야 한다.
- QR의 메뉴 ID는 주문 의사 표현일 뿐 가격·재고·결제 권한을 증명하지 않는다.
- 백엔드 연결 시 입력 길이, 허용 매장 키, 메뉴 ID 형식과 개수를 서버에서 다시 검증해야 한다.

## 11. 수용 기준

- `Prepped`가 모바일, 키오스크, PWA, 검색·공유 metadata에 일관되게 표시된다.
- 모바일에서 메뉴 저장 후 QR이 갱신된다.
- 모바일에서 `내 설정`을 열어 매장별 저장 메뉴를 확인하고 메뉴 생성 흐름으로 수정할 수 있다.
- 메인 QR에서 모든 매장 링크를, 매장 행에서 해당 매장 링크를 복사할 수 있다.
- 유효한 공유 링크는 읽기 전용 QR을 표시하고 기기의 기존 저장 메뉴를 변경하지 않는다.
- 잘못된 공유 query는 로컬 QR을 유지하고 오류를 안내한다.
- 키오스크가 카메라 또는 샘플 코드로 QR 원문과 메뉴 ID를 표시한다.
- QR 문자열 문법과 브라우저 로컬 저장 경계가 코드와 문서에서 일치한다.
- `/`와 `/kiosk`가 프로덕션에서 모두 제공된다.
- `npm run build`가 성공한다.
