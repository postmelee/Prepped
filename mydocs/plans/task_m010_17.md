# Task M010 #17 수행계획서

GitHub Issue: [#17](https://github.com/postmelee/Prepped/issues/17)
마일스톤: M010

## 목적

해커톤 제출물의 첫 화면인 README 상단에 심사위원이 즉시 사용할 수 있는 공개 링크와 짧은 평가 동선을 제공한다. 모바일 PWA와 키오스크가 서로 다른 기기·역할을 갖는다는 점을 처음 보는 사람도 이해하고, 3~5분 안에 메뉴 준비부터 QR 스캔과 메뉴 복원까지 핵심 가치를 확인할 수 있게 한다.

카메라를 사용할 수 없는 심사 환경도 고려해 샘플 QR 또는 수동 입력 대체 경로와 예상 결과를 함께 안내한다. 실제 POS 주문과 결제는 데모라는 현재 경계를 상단에서 분명히 표시한다.

## 배경

Issue #6에서 README를 사용자 중심 제품·개발·아키텍처 소개로 개편했으나, 공개 모바일·키오스크 URL과 심사위원용 테스트 시나리오는 상단에 없다. 이 저장소 자체가 해커톤 제출물이므로 심사위원이 별도 배포 문서나 하단 개발 섹션을 찾지 않고 바로 체험할 수 있어야 한다.

공개 모바일 PWA와 `/kiosk`는 2026-08-16 사전 확인에서 HTTP 200을 반환했다. 현재 앱은 모바일 메뉴 설정·공유 QR과 키오스크 카메라·샘플·수동 QR 입력을 제공한다. 이 task는 그 기능을 변경하지 않고 README의 진입 동선만 개선한다.

## 범위

### 포함

- README 제목과 핵심 문구 직후의 `심사위원 빠른 체험` 섹션
- 공개 모바일 PWA, 키오스크, 필요 시 샘플 공유 QR 링크
- 권장 기기·브라우저 구성과 예상 소요 시간
- 카메라 기반 3~5분 핵심 시나리오와 단계별 예상 결과
- 카메라 없는 환경의 샘플 QR·수동 입력 대체 시나리오
- 실제 POS·결제와 실시간 가격·재고의 데모 경계 안내
- 링크 응답, Markdown 구조, 기존 제품 설명과 자동 회귀 검증

### 제외

- 애플리케이션 코드와 사용자 인터페이스 변경
- QR payload, 로컬 저장소 또는 API 계약 변경
- 신규 Sites 버전 저장·공개 배포와 AWS 변경
- 백엔드, POS, 실제 결제 구현
- 신규 이미지·동영상 제작
- 기존 제품·아키텍처·개발 안내의 전면 재작성

## 설계 방향

- 저장소 랜딩 화면에서 바로 보이도록 H1·핵심 문구 다음, 장문 제품 설명 이전에 체험 안내를 둔다.
- 링크 표 또는 짧은 목록으로 모바일 PWA와 키오스크의 역할을 함께 표시한다.
- 권장 시나리오는 `열기 → 메뉴 준비 → QR 표시 → 매장 선택·스캔 → 복원 결과 확인` 순서로 작성한다.
- 카메라 대체 경로는 `/kiosk` 내부의 샘플 QR과 수동 입력을 사용해 별도 데이터나 임시 서비스를 만들지 않는다.
- 기대 결과와 데모 한계를 바로 옆에 적어 성공 기준과 미구현 범위를 동시에 전달한다.
- 하단 `로컬 개발`과 `검증` 섹션은 기여자용 정보로 유지하고 상단 심사 동선과 중복되는 설명만 최소화한다.

## 잠정 단계

- **Stage 1 — 빠른 체험 링크와 환경 안내**
  - README 상단에 모바일 PWA·키오스크 링크, 예상 소요 시간과 권장 기기 구성을 추가한다.
  - 공개 URL 응답과 상단 발견성, 기존 제품 소개 보존을 확인한다.
- **Stage 2 — 심사 시나리오와 대체 경로**
  - 카메라 기반 핵심 시나리오, 카메라 없는 대체 절차, 예상 결과와 데모 경계를 추가한다.
  - 현재 UI·QR 계약과 문구가 일치하고 과장된 기능 표현이 없는지 확인한다.
- **Stage 3 — 통합 검증과 제출 준비**
  - 외부·내부 링크, Markdown 구조, 전체 자동 테스트와 diff 범위를 검증한다.
  - 최종 보고서와 `devel` 대상 PR에 사용할 근거를 확정한다.

## 검증 계획

### 단계별 검증

- Stage 1
  - 공개 `/`, `/kiosk` URL HTTP 200 확인
  - `sed -n '1,100p' README.md`로 상단 배치와 링크 역할 확인
  - `git diff --check`
- Stage 2
  - README 시나리오를 현재 `/`, `/kiosk`, QR payload 계약과 대조
  - 카메라·샘플·수동 입력, 예상 결과, 데모 경계 핵심어 확인
  - `git diff --check`
- Stage 3
  - README 내부 상대 링크 존재와 외부 체험 URL 응답 검사
  - 제목 계층·fenced block·Mermaid 구조 검사
  - `npm test`
  - `git diff --check origin/devel...HEAD`

### 통합 검증

- README 첫 화면에서 모바일 PWA와 키오스크 링크, 권장 환경과 예상 소요 시간을 찾을 수 있다.
- 카메라 기반 3~5분 시나리오와 카메라 없는 대체 시나리오가 모두 있다.
- 단계별 예상 결과와 실제 POS·결제가 데모라는 경계가 명확하다.
- 기존 사용자 소개·아키텍처·개발 안내가 보존된다.
- 공개 체험 URL이 응답하고 내부 링크 대상이 존재한다.
- 전체 자동 테스트가 통과한다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **공개 배포와 저장소 시점 차이**: README가 아직 공개되지 않은 기능을 지시하지 않도록 현재 라이브 화면과 문구를 대조한다.
- **카메라 권한 제약**: HTTPS·브라우저 권한 필요성을 적고 샘플·수동 입력 경로를 함께 제공한다.
- **상단 과밀화**: 링크, 권장 환경, 핵심 절차만 상단에 두고 개발 상세는 기존 하단 섹션을 유지한다.
- **외부 URL 변경**: 검증 시 HTTP 상태를 기록하고 기존 Sites URL을 단일 진실 원천으로 사용한다.

## 승인 요청 사항

- README 루트를 심사위원용 공식 진입 문서로 유지하는 위치 판단
- 상단 빠른 링크, 카메라·비카메라 시나리오와 데모 경계 구성
- 애플리케이션·배포를 변경하지 않는 제외 범위
- 작업지시자가 PR 생성까지 별도 승인 없이 진행하도록 명시 승인했으므로 이 계획 승인 후 구현계획서와 Stage 1~3, 최종 보고·PR 게시까지 연속 진행
