# Task #7 수행계획서 — 실메뉴 카탈로그 API와 다중 매장 QR·키오스크 연동 구축

GitHub Issue: [#7](https://github.com/postmelee/Prepped/issues/7)
마일스톤: M010

## 목적

맥도날드, 서브웨이, 스타벅스의 실제 메뉴명과 공식 이미지 참조를 수집해 매장별 옵션·변형을 표현할 수 있는 카탈로그를 구축한다. 웹앱은 메뉴 조회 API를 통해 전체 메뉴를 보여주고, 사용자가 여러 매장의 메뉴를 미리 설정해 기존 QR 문자열 계약으로 저장할 수 있어야 한다.

키오스크는 사용자가 대상 매장을 먼저 선택한 뒤 QR을 인식한다. 스캔한 원문에서 선택 매장 그룹만 추출하고, 포함된 메뉴 ID를 카탈로그 API의 메뉴와 대응해 제품명·이미지·선택 옵션을 화면에 보여준다.

## 배경

기존 모바일 앱은 맥도날드 목업 메뉴만 정적으로 포함하고, 키오스크는 QR에서 추출한 매장 키와 숫자 ID를 원문 수준으로만 표시한다. 또한 Issue #3은 주문 초안 중심의 공통 AWS 백엔드 기반을, Issue #4는 매장별 내 설정 화면 흐름을 각각 담당하므로, 이번 작업은 두 결과를 보존·연결하면서 실메뉴 카탈로그와 QR-키오스크 종단 흐름을 별도 Issue로 완성해야 한다.

사전 조사에서 세 브랜드 공식 웹사이트가 제품명과 이미지 URL을 제공함을 확인했다. 다만 가격은 일부 사이트에서만 제공되고 공식 이미지의 재배포 권한은 별도 확인이 필요하므로, 수집 시점·출처·가격 유형·이미지 사용 상태를 데이터에 명시한다.

## 범위

### 포함

- 맥도날드, 서브웨이, 스타벅스 공식 메뉴 페이지 수집기와 재현 가능한 카탈로그 시드
- 매장, 메뉴, 변형, 옵션 그룹, 옵션 값, 가격 출처, 이미지 출처를 표현하는 DynamoDB 단일 테이블 카탈로그 모델
- 매장 목록, 매장별 전체 메뉴, 메뉴 상세, 메뉴 ID 일괄 해석 API와 계약·테스트
- Issue #3 백엔드 기반을 의존 관계로 가져오고 카탈로그 저장소·서비스·HTTP 핸들러·배포 자원 추가
- Issue #4 모바일 화면 흐름을 유지한 채 API 메뉴 목록, 매장별 메뉴 설정, 로컬 저장 상태, 다중 매장 QR 생성 연동
- 기존 `store={menuId,menuId};store={menuId}` QR 문법을 유지하는 버전 내 호환 파서·직렬화기
- `/kiosk` 매장 키오스크 선택, QR 스캔/수동 입력, 선택 매장 그룹 필터링, API 메뉴 매칭 및 결과 표시
- 기존 저장 데이터와 QR 문자열 호환, 단위·통합·빌드·브라우저 검증

### 제외

- 결제, 실제 주문 전송, POS·재고·매장별 실시간 품절 연동
- 계정 기반 서버 동기화와 브라우저 로컬 설정의 서버 저장
- 이미지 권리 확인 전 공식 이미지 바이너리의 저장소·오브젝트 스토리지 재배포
- QR 계약을 깨는 자유형 옵션 객체 삽입과 메뉴 ID 이외의 신규 토큰 문법
- 공식 사이트가 제공하지 않는 가격의 정확성 보증. 필요한 경우 `estimated`로 표시한 임의 가격 사용
- Issue #3의 주문 초안 API·공통 인증·관측성 범위를 중복 구현하는 작업

## 설계 방향

- QR 원문 계약은 `store={menuId,menuId}`를 유지하고 여러 매장은 세미콜론으로 구분한다. 옵션·변형은 카탈로그에서 안정적인 메뉴 ID 자체가 가리키는 주문 가능 항목으로 정규화한다.
- 외부 노출 ID는 브랜드 단축키가 포함된 안정적 문자열로 정의한다. 공식 사이트의 변경 가능한 숫자 ID는 `sourceProductId`로 별도 보관한다.
- 카탈로그는 읽기 중심 단일 테이블로 설계하고, 매장·카테고리별 목록과 ID 일괄 해석 접근 패턴을 우선한다. 실제 AWS 테이블 및 HTTP 런타임은 Issue #3의 백엔드 스캐폴드에 확장한다.
- 수집기는 공식 페이지의 사실 데이터만 원본 스냅샷으로 변환한다. 가격이 없으면 합리적 임의 가격을 원화로 넣되 `priceType: estimated`를 강제한다.
- 공식 이미지는 원본 URL·출처 페이지·수집 시점을 기록한다. 로컬 개발과 재배포 기본값은 플레이스홀더이며, 권리 확인 또는 원격 로딩 정책이 명확한 환경에서만 공식 URL을 표시한다.
- 모바일은 API 로딩·오류·재시도 상태를 제공하고 설정을 브라우저 저장소에 매장별로 유지한다. 편집 중 임시 상태가 다른 매장 또는 탭 이동으로 손실되지 않는 Issue #4 동작을 보존한다.
- 키오스크는 키오스크 매장을 먼저 고정한 뒤 QR에서 해당 키만 선택한다. 다른 매장 데이터는 무시하며, 알 수 없는 ID는 명시적으로 구분해 부분 성공을 허용한다.
- 현재 브랜치는 Issue #4가 포함된 `publish/task1`을 기준으로 하고, 구현 시 Issue #3의 `develop/backend` 결과를 병합하는 적층 의존 구조를 사용한다. 최종 PR에는 두 선행 작업과 재기준화 필요 여부를 명시한다.

### 통합 검증

- 세 매장의 수집 시점 전체 활성 메뉴가 API 목록에 나타나고 각 항목이 고유한 안정 ID를 가진다.
- 옵션·변형이 있는 메뉴는 카탈로그 상세에서 선택 가능 범위와 기본값을 표현한다.
- 모바일에서 두 개 이상 매장의 메뉴를 설정하면 기존 문법의 단일 QR에 매장별 그룹이 들어간다.
- 키오스크가 선택한 매장 그룹만 읽고 메뉴 ID를 제품명·이미지·옵션과 매칭한다.
- 기존 `mcdonald={...}` 및 현재 로컬 저장 데이터가 회귀 없이 마이그레이션된다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **공식 사이트 구조 변경·차단**: 수집기는 사이트별 어댑터와 검증 실패를 분리하고, 수집 시점 스냅샷을 커밋해 런타임이 외부 사이트 가용성에 의존하지 않게 한다.
- **이미지 저작권·핫링크 정책**: URL과 출처만 보관하고 기본 UI는 플레이스홀더 정책을 적용한다. 바이너리 재배포는 권리 확인 후 별도 작업으로 남긴다.
- **가격 비공개·지역 차이**: 공식 가격과 임의 가격을 구분하는 `priceType`/`priceSource`를 강제하고 UI에 추정값임을 표시한다.
- **대규모 메뉴와 QR 길이**: QR에는 선택된 안정 ID만 저장하고 카탈로그 상세를 넣지 않는다. 저장 가능 개수와 QR 용량을 통합 검증한다.
- **선행 브랜치 의존**: #3과 #4의 소유 범위를 변경하지 않고 병합 커밋과 최종 PR 설명에 적층 관계를 기록한다.
- **배포 자격 증명 부재**: 로컬·계약·템플릿 검증을 완결하고, 외부 배포 스모크만 명확히 조건부 결과로 보고한다.
