# Task #7 카탈로그 출처·수집 가능성 조사

조사일: 2026-08-16 (Asia/Seoul)
대상: 대한민국 공식 메뉴 페이지

## 결론

세 브랜드 모두 공식 웹페이지에서 제품명과 이미지 URL을 기술적으로 읽을 수 있다. 맥도날드와 스타벅스는 공식 가격을 공개 메뉴 목록에서 안정적으로 얻기 어렵고, 서브웨이는 공식 모바일/개발 페이지에서 일부 가격을 확인할 수 있으나 페이지별 제품 ID가 일치하지 않는 경우가 있다.

따라서 카탈로그는 제품명·공식 제품 ID·상세/목록 URL·이미지 원본 URL을 출처와 수집 시각과 함께 저장한다. 가격은 `official`과 `estimated`를 구분하며, 이미지 바이너리는 권리 확인 없이 저장소나 오브젝트 스토리지에 복제하지 않는다.

## 브랜드별 조사

### 맥도날드

| 항목 | 확인 내용 |
|---|---|
| 공식 목록 | [맥도날드 메뉴](https://www.mcdonalds.co.kr/kor/menu/list.do) |
| 공식 상세 예시 | [빅맥](https://www.mcdonalds.co.kr/kor/menu/detail.do?seq=178) |
| 수집 가능 필드 | 메뉴명, 카테고리, 상세 페이지 `seq`, 설명·영양 정보, 공식 이미지 URL |
| 가격 | 공개 목록·상세에서 일관된 판매 가격을 확인하기 어려움. `estimated` 사용 |
| 옵션 모델 | 단품/세트, 사이즈, 음료·사이드 변경, 일부 재료 제외 가능성을 옵션 그룹으로 표현 |
| 주의 | 메뉴와 판매 여부·가격은 시간·매장·배달 여부에 따라 달라질 수 있음 |

### 서브웨이

| 항목 | 확인 내용 |
|---|---|
| 공식 목록 | [써브웨이 샌드위치](https://www.subway.co.kr/menuList/sandwich) |
| 주문 단계 | [써브웨이 이용방법](https://www.subway.co.kr/utilizationSubway) |
| 재료 정보 | [써브웨이 신선한 재료 소개](https://www.subway.co.kr/freshInfo) |
| 수집 가능 필드 | 메뉴명, 분류, 설명, 영양 정보, 제품 링크 ID, 공식 이미지 URL |
| 가격 | 일부 공식 모바일/개발 화면에서 확인 가능. 출처가 확인된 항목만 `official`, 나머지는 `estimated` |
| 옵션 모델 | 15cm/30cm, 빵, 치즈, 추가 토핑, 야채 제외, 소스, 세트 구성 |
| 주의 | 정식·모바일/개발 페이지 사이에서 같은 상품의 숫자 ID가 달라 안정 외부 ID로 사용할 수 없음 |

조사 시 공식 화면에서 에그마요 가격 예시로 15cm 6,200원, 30cm 11,800원을 확인했다. 이 값은 전체 매장·시점의 가격 보증이 아니므로 원본 페이지와 수집 시각을 함께 기록한다.

### 스타벅스

| 항목 | 확인 내용 |
|---|---|
| 공식 음료 목록 | [스타벅스 음료](https://www.starbucks.co.kr/menu/drink_list.do) |
| 수집 가능 필드 | 한글·영문 제품명, 카테고리, `product_cd`, 영양 정보, 공식 이미지 URL |
| 가격 | 공개 메뉴 목록에서 판매 가격을 안정적으로 얻기 어려움. `estimated` 사용 |
| 옵션 모델 | HOT/ICED, 사이즈, 샷, 시럽, 우유, 휘핑, 드리즐 등 퍼스널 옵션 |
| 주의 | HOT/ICED가 서로 다른 `product_cd`를 가지는 제품이 있어 주문 가능 변형을 별도 메뉴 ID로 정규화해야 함 |

조사 예시로 카페 아메리카노 HOT은 `product_cd=94`, ICED는 `product_cd=110563`으로 확인했다. 두 항목은 QR에서 직접 선택 가능한 별도 카탈로그 메뉴가 된다.

## 식별자 정책

- 공식 숫자 ID는 `source.productId`에 원문 그대로 저장한다.
- QR/API용 `menu.id`는 `{storeKey}-{product-slug}-{variant}` 형태의 소문자 영문·숫자·하이픈 문자열로 고정한다.
- 같은 제품의 15cm/30cm, HOT/ICED처럼 주문 결과를 바꾸는 핵심 변형은 서로 다른 `menu.id`를 가진다.
- 재료 제외·소스·우유처럼 조합 수가 큰 커스텀은 옵션 그룹으로 저장한다. v0.1.0 원문 QR에는 별도 옵션 객체를 넣지 않으므로 키오스크는 기본값과 가능한 옵션을 표시한다.
- ID 재발급은 기존 QR을 깨므로 제품명이 바뀌어도 동일 제품·변형이면 ID를 유지한다.

## 가격 정책

```ts
type Money = {
  amount: number;
  currency: "KRW";
  type: "official" | "estimated";
  sourceUrl?: string;
  note?: string;
};
```

- `official`: 공식 페이지에서 상품·변형·통화가 직접 대응되는 가격만 사용한다.
- `estimated`: 공식 가격을 얻을 수 없을 때 UI 데모와 합계 계산을 위한 임의 가격이다.
- 프론트엔드는 추정 가격을 `예상 가격`으로 표시하고 결제 금액으로 신뢰하지 않는다.
- 키오스크 주문 확정 전 실제 POS 가격·판매 여부를 다시 확인해야 하며 이 연동은 이번 범위 밖이다.

## 이미지 정책

- `source.imageUrl`은 사실 데이터의 출처 참조이며 소유권이나 재배포 허가를 뜻하지 않는다.
- `imageUsage` 기본값은 `reference-only`다.
- 권리 확인 전 크롤러와 시드 작업은 이미지 파일을 내려받거나 저장소/R2에 복사하지 않는다.
- 웹 UI는 공식 원격 이미지 표시가 실패하거나 허용되지 않아도 동작하는 브랜드별 플레이스홀더를 제공한다.
- 이미지 바이너리 재배포가 필요하면 브랜드 가이드·이용약관·서면 허가를 확인하는 별도 Issue로 진행한다.

## 수집기 안전 조건

- 공식 도메인만 허용하고 리디렉션 결과의 호스트도 다시 검사한다.
- HTML 필수 선택자와 브랜드별 최소 항목 수를 검증하며, 0건·급감은 성공으로 커밋하지 않는다.
- 수집은 수동 갱신 명령으로 실행하고 웹앱 런타임 요청에서 공식 사이트를 직접 크롤링하지 않는다.
- 새 스냅샷은 고유 ID, 출처 URL, 가격 유형, 옵션 참조를 검증한 뒤에만 기존 파일을 대체한다.
- 사이트 이용 조건과 robots 정책이 자동 수집을 허용하지 않거나 불명확하면 수동 검증 자료로 전환한다.
