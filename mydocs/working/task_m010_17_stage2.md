Stage 1의 빠른 링크 아래에 심사위원이 그대로 따라 할 수 있는 카메라 기반 3~5분 시나리오와 카메라 없는 대체 절차를 추가한다. 현재 화면의 실제 버튼명, QR 문법과 데모 경계에 맞춰 각 단계의 예상 결과를 명시한다.

## 본문 변경 정도 / 본문 무손실 여부

Stage 1에서 추가한 상단 섹션에 20줄을 이어 붙였고 기존 README 문장은 삭제하거나 다시 쓰지 않았다. 실제 화면의 `메뉴 만들기`, `이 메뉴로 저장하기`, `카메라 켜기`, `다중 매장 샘플 QR로 미리 보기`, `불러오기`, `결제하기` 버튼명을 사용했다.

수동 입력 예시는 자동 테스트가 사용하는 세 매장 안정 ID를 조합했다. 결제 버튼 뒤 화면은 실제 POS·PG 처리가 아닌 사용자 흐름 데모이며, 가격·재고도 실시간 보증이 아니라는 경계를 함께 표시했다.

## 검증 결과

실행 명령:

```bash
rg -n '메뉴 준비|QR|매장 선택|스캔|예상 결과|카메라가 없다면|샘플 QR|수동 입력|POS|결제' README.md
rg -n '샘플 QR|수동|매장 선택|결제' app/kiosk/page.tsx
rg -n '메뉴 만들기|내 한끼 QR 복사|공유' app/page.tsx app/lib/qr-share.ts
sed -n '60,165p' docs/technical-specification.md
git diff --check
```

결과:

- OK — README 18~27행에 모바일 메뉴 저장, 같은 매장 키오스크 선택, 카메라 허용과 QR 스캔 순서가 있다.
- OK — 메뉴 저장 뒤 QR 정보 갱신과 스캔 뒤 선택 매장 메뉴 복원을 각각 예상 결과로 명시했다.
- OK — README 29~36행에 카메라 없는 환경의 샘플 QR과 원문 수동 입력 두 대체 경로가 있다.
- OK — 수동 예시는 `mcdonald`, `subway`, `starbucks` 그룹과 현재 카탈로그 안정 ID를 사용한다.
- OK — 모바일 버튼명은 `app/page.tsx`, 키오스크 버튼명은 `app/kiosk/page.tsx`의 현재 UI와 일치한다.
- OK — 키오스크가 선택 매장 그룹만 복원하고 카메라가 없으면 샘플·수동 입력을 쓴다는 설명이 기술 명세 4.1·4.3·6절과 일치한다.
- OK — 실제 POS 주문·결제와 실시간 가격·재고를 수행하지 않는다는 주의를 시나리오 바로 아래에 표시했다.
- OK — Stage 2 README diff는 20줄 추가, 삭제 0줄이고 `git diff --check`가 통과했다.

## 잔여 위험

- 실제 기기 카메라 스캔은 심사위원의 브라우저 권한과 하드웨어에 의존한다. README가 제공하는 샘플·수동 입력으로 핵심 파싱 흐름은 대체할 수 있다.
- GitHub에서 README 표와 중첩 목록이 시각적으로 렌더링되는 최종 결과는 PR 화면에서 확인해야 한다.
