## 단계 목적

Stage 1에서 구현한 세 화면 하단 탐색과 매장별 설정 조회·수정 계약을 공식 문서와 자동 테스트에 반영하고, 실제 브라우저에서 모바일 핵심 시나리오와 키오스크 기존 흐름을 검증한다.

## 산출물

| 파일 | 변경 요약 |
|---|---|
| `README.md` | 모바일 PWA 화면 목록에 `내 설정`의 매장별 메뉴·합계·QR 상태 확인과 수정 기능 추가 |
| `docs/technical-specification.md` | 3개 하단 탐색, `aria-current`, 매장별 설정 데이터 파생·수정 흐름, 접근성·수용 기준 명문화 |
| `tests/rendered-html.test.mjs` | 모바일 SSR의 `내 설정`·현재 탐색 표식과 설정 화면 소스 계약 회귀 검사 추가 |

## 본문 변경 정도 / 본문 무손실 여부

README와 기술 명세의 기존 QR·키오스크·PWA·보안 내용은 유지하고 모바일 사용자 표면과 메뉴 선택 모델에 설정 화면 내용을 추가했다. 자동 테스트도 기존 세 테스트를 유지한 채 모바일 내비게이션과 설정 화면 계약을 강화했다. QR serializer/parser 정규식, manifest, 카메라와 결제 표식 검사는 그대로 남아 있다.

## 검증 결과

실행 명령:

```bash
npm test
npm run build
git diff --check
```

결과:

- OK — 모바일 SSR, 키오스크 SSR, PWA·QR 계약 테스트 3개가 모두 통과했다.
- OK — vinext build가 `/`, `/kiosk` 두 경로를 포함해 성공했다.
- OK — `git diff --check`가 경고 없이 통과했다.

브라우저 시나리오:

- OK — `내 설정` 하단 아이콘을 누르면 현재 항목의 `aria-current="page"`와 `내 설정 메뉴` 제목이 확인됐다.
- OK — 기존 로컬 조합 4개의 이름·가격과 19,100원 합계, `QR 사용 중` 상태가 맥도날드 카드에 표시됐다.
- OK — 서브웨이는 `설정 없음`, `준비 중`, 비활성 안내만 표시됐다.
- OK — 설정 화면 `메뉴 바꾸기`가 기존 매장 선택 단계로 이동했고 기존 4개 메뉴를 선택 상태로 유지했다.
- OK — 불고기 버거를 추가하고 저장한 뒤 QR payload가 `mcdonald={101,201,301,103,102}`로 갱신됐다.
- OK — 설정 화면 재진입 시 5개 메뉴와 22,600원 합계가 즉시 반영됐다.
- OK — 키오스크 샘플 QR에서 원문 `mcdonald={101,201,301}`과 ID 101·201·301, 결제 완료 화면을 확인했다.

시각 검수:

- OK — 480px 모바일 앱 폭에서 두 매장 카드, 긴 목록, 합계와 행동 버튼이 겹치지 않았다.
- OK — 3열 하단 탐색의 QR·더하기·설정 아이콘과 짧은 레이블이 구분되고 현재 설정 항목의 녹색 상태가 명확했다.
- OK — 메뉴 행의 이름·가격, 상태 배지와 행동 버튼이 큰 글자와 고대비 구조를 유지했다.

## 잔여 위험

- 실제 저장 내용은 브라우저별 `localStorage`에만 있으므로 다른 기기와 동기화되지 않는다.
- 서브웨이는 화면에 확장 지점만 보이며 실제 선택 데이터는 아직 없다.
- 실제 휴대폰 QR과 노트북 카메라 조합의 하드웨어 종단 검증은 사용자 기기에서 별도로 필요하다.
